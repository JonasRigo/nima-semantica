# Calculate Mathematics

Use the `nima_math_*` MCP tools as a research harness over one private calculation graph.
You own mathematical strategy, interpretation and stopping; the controller owns identities, revisions, provenance links, receipts and represented admission checks.
Establish the requested outputs and task definitions, conditions, dimensions and units; preserve the original session binding.

## Discover the calculation

Treat the task as novel: a ready-made solution may not exist.
Retrieve missing atomic definitions or general methods when useful, then calculate and test alternatives.
Do not spend exploration trying to qualify a remembered answer.
For a consequential disputed premise, construct the missing relation from definitions or independent computation rather than checking only its consequences.

Explore with isolated Python and record introduced assumptions provisionally.
Name inputs and intermediate steps, distinguishing given definitions from guesses.
The graph retains receipts and unresolved support throughout; an open support obligation does not prevent further investigation.
Routine responses show results and concrete diagnostics rather than the qualification backlog.
Inspect exact nodes or receipts when needed, especially after a failed operation or contradictory observation.
Execution and internally consistent consequences do not prove a premise.

Represent the successful calculation with atomic graph operations.
Inputs need exact provenance or explicit assumptions; computed steps inherit their actual dependencies.
The controller generates Python from those operations.
Use `reuse` for existing compiled definitions instead of transcribing them.
For exploration-to-graph reconstruction, use `reconstructs_receipt` and inspect the reported comparisons; only listed observed representations are compared, not physical truth.
Do not automatically promote exploratory stdout into evidence.
Label domain applications explicitly; arithmetic literals do not establish physical coefficients or multiplicities.
Consult [operation guidance](references/operations.md) for the exact construction, reuse and source-selection interfaces.

## Qualify the selected candidate

When a candidate survives substantive mathematical checks, request `frontier` with its selected `support_nodes` (or inspect the controller's current candidate).
Resolve only the obligations affecting that candidate; historical attempts remain available through inspection/export.
Use existing substantiation tools with exact applicable sources or independent qualified calculations.
Select `method_span` to let the controller copy an exact source quotation; citation accuracy alone does not establish applicability.
If qualification reveals a mathematical gap, return to exploration rather than merely defending the candidate.

Submit the selected `support_nodes` and omit `answer`: the controller copies their exact values and applies unchanged admission checks.
Admission is not an absolute mathematical certificate.
Close completed only after current admission, or close partial with the candidate and precise unresolved prerequisite.
A failed search for a complete formula alone is not a reason to stop when independent calculation remains available.

## Execution discipline

Run session mutations sequentially, including retrieval; await the returned revision before the next mutation.
Read-only status, frontier, inspection and export may run concurrently.
Use a new request ID for a new action; replay uncertain delivery only with identical arguments.
Never automatically retry interrupted execution.
Tool access does not authorize changing scope, enabling capabilities, ingesting sources, publishing graphs or spending beyond user approval.
Private graph export does not record project progress; use separately authorized research-recording tools when required.
