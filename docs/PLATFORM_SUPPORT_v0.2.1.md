# v0.2.1 qualification

The supported targets remain Ubuntu 24.04 and native Apple-silicon macOS, with Python 3.11–3.13 and pinned Langflow 1.12.0.
The v0.2.1 GitHub release records the exact qualified public commit, hosted workflow run, distribution checksums and platform test counts.
The [tests workflow](https://github.com/JonasRigo/nima-semantica/actions/workflows/tests.yml) builds the curated package and installs its wheel outside the source tree for all nine core and three Langflow jobs, together with the packaging job.

Focused acceptance covers configured index limits, larger-budget recovery without repeated preparation, source readability and integrity, scoped receipts, unchanged source/graph identities and explicit owner routing.
Vocabulary acceptance covers disabled/unavailable behavior, scope and content hashes, complete definition readback, stale references, provisional extensions and disagreement, model-call counts and preexisting private-session compatibility.
Qualification includes complete source and installed-wheel suites, preservation of preexisting v0.2.0 records and creation/action replays, and fresh configured Langflow and private HTTP/stdio clients.
The fresh toolbox exercises all 21 published workflows, indexing-only recovery and the vocabulary skill’s header, seal, validation, publication, context and exact readback path.
Managed-image checks use isolated stores and leave existing research deployments on their selected version.

A fixed 12-pair configured-model evaluation uses the existing OpenRouter `gpt-6-luna` profile, with one call for each enabled/disabled condition and no extra controller review call.
The model distinguishes supplied definitions, retains provisional exploration and treats an embedded source instruction as data in these fixtures.
Findings can still over-identify concerns or select debatable categories, and guidance increases prompt size and may increase latency.
It does not establish scientific truth, novelty or exhaustive semantic correctness.
Optional provider and remote-worker skips are reported explicitly; hosted macOS does not qualify Docker Desktop integration.
Historical v0.2.0 Lean and deployment evidence remains available at its original version and is not presented as fresh execution of the changed implementation.
